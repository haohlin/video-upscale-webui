# SeedVR2 Restoration Modes and Reliable Progress Design

## Status

Approved direction, awaiting design-spec review before implementation.

## Goals

- Keep one private, Tailscale-served WebUI for all supported video restoration work.
- Focus first release on generative SeedVR2 restoration; do not add DPIR or conventional filters.
- Add selectable output scales: original resolution (`1x`), half resolution (`0.5x`), quarter resolution (`0.25x`, experimental), and current double resolution (`2x`).
- Report measured phase and batch progress from SeedVR2 instead of inferring progress from elapsed wall time.
- Show elapsed time for every active job and an honest ETA range with confidence.
- Maintain WebUI-specific SeedVR2 changes in a public fork that can follow upstream and support future pull requests.
- Preserve loopback-only binding, private Tailscale access, bounded processing, persistent results, and manual deletion.

## Non-goals

- No DPIR, Real-ESRGAN, or other non-generative restoration engine in this release.
- No engine chaining.
- No promise that downscaled processing can preserve original-resolution fine detail.
- No fake linear percentage while SeedVR2 has not emitted measured work counters.
- No automatic runtime restart while an existing job is running.
- No upstream pull request in this release; fork changes should merely remain suitable for one.

## User Experience

### Restoration profile

First release keeps SeedVR2 3B Safe as recommended model and SeedVR2 7B FP8 as experimental. Model choice remains distinct from output scale.

### Output scale

WebUI adds one output-scale selector:

- `1x Original` — output matches source dimensions. Full generative restoration. Default.
- `0.5x Balanced` — width and height are half source dimensions. Full generative restoration at one quarter the output pixels.
- `0.25x Fast` — width and height are one quarter source dimensions. Experimental; shortest edge must still satisfy a safe minimum.
- `2x Upscale` — width and height are doubled. Existing behavior and highest cost.

Scale calculations use source dimensions, preserve aspect ratio, round codec dimensions to even values, and pass the resulting shortest edge to SeedVR2. UI displays calculated output dimensions before upload when media metadata is available; backend remains authoritative after validation.

Downscaled modes resize before SeedVR2 inference. They therefore remain generative restoration, but output remains smaller. UI must state this clearly.

### Active job display

Every active job shows:

- current phase and current batch or chunk when known;
- measured overall percentage when upstream work counters exist;
- elapsed wall time;
- ETA as a range, for example `45–60 min`;
- confidence: `low`, `medium`, or `high`;
- `Calibrating…` until sufficient current-run or historical evidence exists;
- a stale-progress warning when process remains alive but no heartbeat or progress event arrives within the configured threshold.

ETA never shows a single falsely precise finish timestamp. Progress remains below 100% until final MP4 validation succeeds.

## SeedVR2 Fork Strategy

Create `haohlin/ComfyUI-SeedVR2_VideoUpscaler` as a GitHub fork of `numz/ComfyUI-SeedVR2_VideoUpscaler`.

Fork repository layout:

- `upstream` remote: `https://github.com/numz/ComfyUI-SeedVR2_VideoUpscaler.git`
- `origin` remote: user fork
- `main`: tracks upstream `main` without WebUI-specific commits
- `feature/cli-progress-events`: contains structured CLI progress support and its tests

The WebUI runtime installer clones the fork and pins an exact reviewed commit from `feature/cli-progress-events`. Updating the fork, pinned commit, dependency lock, and model registry remains an explicit reviewed operation.

Fork change adds opt-in machine-readable events to standalone CLI. Default human-readable behavior must stay compatible with upstream. Proposed CLI option:

```text
--progress_format jsonl
```

Each event is one bounded JSON object on stdout with a stable schema and immediate flush. Event types:

- `model_preparation_started`
- `model_preparation_completed`
- `chunk_started`
- `phase_progress`
- `heartbeat`
- `output_started`
- `completed`

Common fields include schema version, monotonic event sequence, phase, current unit, total units, current frames, chunk index/count, and elapsed seconds where applicable. Events contain no paths, filenames, credentials, environment data, or model-directory values.

The existing phase callbacks become active in standalone single-GPU processing. Phase progress uses actual encode, upscale, decode, and postprocess counters already generated by SeedVR2. Chunk counts wrap those phase counters for streaming inputs.

## Progress Model

### Measured work

WebUI adapter consumes fork JSONL and emits a private structured line protocol to backend. Backend validates schema, bounds every numeric and string field, ignores unknown fields, and persists only required metrics.

Overall percentage uses SeedVR2's existing phase weighting as initial semantics:

- encoding: 20%
- DiT upscaling: 25%
- decoding: 50%
- post-processing: 5%

For chunked processing, each chunk contributes its fraction of total frames. Model preparation is displayed as a stage but does not advance measured generation percentage. Final remux occupies a small separately measured completion segment while displayed percentage remains capped at 99%.

Phase weights are progress-display weights, not ETA-time assumptions. Historical timings determine ETA phase cost.

### Heartbeats

Fork emits a bounded heartbeat during long operations even when no batch completes. Backend records `last_heartbeat_at`. UI distinguishes:

- active and reporting;
- active but progress signal stale;
- failed or cancelled.

A stale heartbeat does not automatically kill processing. Existing configured processing deadline and cancellation behavior remain authoritative.

## ETA Model

### Always reliable

`started_at` and current server time provide elapsed wall time. Completion records `finished_at` and final elapsed duration.

### Calibration inputs

ETA uses, in priority order:

1. current job's completed units within current phase;
2. current job's completed phases;
3. comparable completed local jobs;
4. no estimate, shown as `Calibrating…`.

Comparable historical samples match:

- SeedVR2 model/profile;
- output-scale mode;
- device/backend identity class;
- output pixel-frame workload bucket;
- batch, chunk, tiling, and precision settings.

History is local SQLite data, never uploaded. Failed, cancelled, interrupted, stale-heartbeat, or configuration-mismatched runs do not train the estimator.

### Estimation

Within a phase, use a bounded exponentially weighted moving average of seconds per completed unit. Remaining phases use matching historical phase rates normalized by output pixel-frames. When history is sparse, use wider quantile-derived bounds rather than a point estimate.

ETA response fields:

- `elapsed_seconds`
- `eta_low_seconds`
- `eta_high_seconds`
- `eta_confidence`: `none`, `low`, `medium`, or `high`
- `progress_source`: `none`, `measured`, or `historical`
- `last_heartbeat_at`

Confidence policy:

- `none`: no completed measured unit and no comparable history;
- `low`: one current unit or one/two comparable runs;
- `medium`: stable current rate across multiple units or at least three comparable runs;
- `high`: stable current rate plus a sufficiently tight comparable historical distribution.

Estimator rejects non-finite values, zero/negative durations, decreasing counters, impossible totals, and extreme rate outliers. ETA range is clamped to configured process deadline.

## Data Model

Add backward-compatible SQLite migrations. Existing jobs remain readable.

`jobs` gains:

- `output_scale` (`2.0` for legacy jobs because existing WebUI jobs always requested 2x; new jobs always store chosen scale)
- `target_width`, `target_height`
- `started_at`, `finished_at`
- `last_heartbeat_at`
- `progress_source`
- `phase_current`, `phase_total`
- `chunk_current`, `chunk_total`
- `eta_low_seconds`, `eta_high_seconds`, `eta_confidence`
- runtime profile fingerprint

A small `job_phase_metrics` table stores phase start/completion times and normalized work counters. Rows persist with job history and are deleted transactionally when operator deletes the job.

Legacy jobs keep original public fields and show no ETA when required timing evidence is absent.

## API Changes

Job creation accepts validated `output_scale` from a fixed allowlist: `0.25`, `0.5`, `1`, `2`. Missing scale uses new configured default `1`.

Public job response adds target dimensions, elapsed/ETA fields, confidence, progress source, phase/chunk counters, and heartbeat state. Existing clients remain functional because fields are additive.

Config endpoint publishes supported profiles, supported scales, default scale, and display labels rather than requiring frontend constants to be authoritative.

No user-controlled command fragments reach a shell. Adapter arguments remain fixed arrays and backend validates scale before process creation.

## Runtime and Deployment

Installer changes:

- clone user fork URL;
- verify expected fork ancestry and exact pinned commit;
- retain upstream remote for controlled sync;
- keep runtime checkout outside WebUI Git repository;
- update dependency locks only if fork change requires them;
- avoid restart when an active job exists;
- expose explicit dry-run and apply behavior for runtime update.

Deployment sequence after both repositories are pushed and current job is terminal:

1. confirm no active job;
2. install pinned fork revision;
3. run health and model checks;
4. restart exact LaunchAgent;
5. submit short low-resolution 1x smoke job;
6. verify progress events, ETA calibration state, MP4/audio output, persistence, and deletion;
7. test private Tailscale URL and confirm loopback binding/Funnel disabled.

## Failure Handling

- Malformed progress event: log bounded diagnostic, ignore event, continue job.
- Event counter regression: reject event and retain prior valid state.
- Progress stream silence: elapsed timer continues; ETA becomes unavailable or stale; job is not killed solely for silence.
- Fork CLI exits nonzero: existing job failure handling applies.
- Backend restart: active job becomes interrupted as today; no stale ETA is reused.
- Missing model or fork revision: health becomes unavailable before job claim.
- Invalid output scale or unsafe target size: reject before queue insertion.
- Output mismatch: fail if final dimensions differ from stored target beyond codec rounding tolerance.

## Security and Privacy

- Keep FastAPI bound to `127.0.0.1`; Tailscale Serve remains only remote entry point.
- Never enable Tailscale Funnel.
- Preserve HTTP Basic authentication and same-origin mutation header.
- Progress JSON must exclude local paths and environment values.
- Bound JSON line length, nesting, string length, counters, and event frequency.
- Keep subprocess execution shell-free.
- Verify fork provenance and pin exact commit.
- Run `codex-security:security-scan` against both fork diff and WebUI before either public push.
- Do not print GitHub credentials or private runtime configuration.

## Future Evaluation

After SeedVR2 path is stable, evaluate generative alternatives as separate engines behind same job contract:

- VEnhancer for configurable 1x–8x refinement;
- DLoRAL for one-step detail-rich restoration on RTX 4090;
- FlashVSR for fast 4x CUDA restoration after RTX 4090 compatibility validation;
- STAR for severe degradation where larger CUDA requirements are acceptable;
- Upscale-A-Video as an older, slower comparison baseline.

Each future engine must provide its own truthful work counters, ETA calibration fingerprint, isolated runtime, license review, and security scan before appearing in WebUI.
